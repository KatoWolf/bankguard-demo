# BankGuard

**Почему перевод попал на проверку и сколько проверок выдержит команда?**

BankGuard помогает антифрод-аналитику исследовать эти вопросы: объясняет риск-балл операции, выстраивает очередь ручной проверки и показывает компромисс между ложными тревогами, пропусками и нагрузкой.

**Это hackathon-прототип на вымышленных данных, не банковская система.** Он не подключён к банку, не выполняет переводы и не блокирует счета. Балл риска не является вероятностью мошенничества.

## Проблема и подход

Необычная операция не обязательно мошенническая, а команда проверки ограничена по времени. Важно не только получить тревогу, но и понять её причины и последствия настройки правил.

BankGuard демонстрирует маршрут **сигналы → объяснение → решение человека → журнал**. Лаборатория позволяет сравнивать настройки, не выдавая синтетический результат за доказанную эффективность в банке.

## Что показать жюри за 3 минуты

1. Открыть **TX-0002** в исходном наборе: 75 баллов = 25 за необычную сумму + 15 за нового получателя + 35 за сообщение о давлении.
2. Добавить вымышленный комментарий и эскалировать кейс. При пороге 50 очередь ожидающих решения сокращается с 6 до 5; реальных действий со счётом нет.
3. В лаборатории сравнить пороги 50 и 1. Ниже ожидаемые результаты для **16 авторских сценариев**, а не банковская статистика:

| Порог | Проверок | Ложных тревог (FP) | Пропусков (FN) | Время при допущении 5 мин/кейс |
|---|---:|---:|---:|---:|
| 50 | 6 | 1 | 2 | 30 мин |
| 1 | 13 | 6 | 0 | 65 мин |

4. Задать лимит проверок, разобрать конкретную ошибку правил, сохранить и восстановить демо-сессию JSON.

## Возможности прототипа

| Раздел | Что можно сделать |
|---|---|
| Мониторинг | Искать и фильтровать операции; открывать следующую тревогу по убыванию риска; смотреть причины, исходные поля и вопросы для ручного разбора. |
| Решения и журнал | Снять кейс с проверки или эскалировать с обязательным комментарием. Черновики сохраняются при переключении кейсов в текущей вкладке. |
| Симулятор | Ввести признаки вымышленного перевода и получить объяснение оценки. Изменение ввода убирает старый результат; пустое числовое поле не считается нулём. |
| Лаборатория | Менять порог 1–100; сравнивать все пороги и базовый 50; смотреть матрицу ошибок, precision/recall, ложные тревоги и пропуски, время и ёмкость команды. |
| Наборы и экспорт | Использовать 16 сюжетных либо 200/1000 воспроизводимых стресс-операций (seed 2026). Выгружать CSV, журнал, пакет кейса, отчёт эксперимента и демо-сессию. |

Пакет кейса разделяет входные поля, сигналы и неподтверждённые гипотезы. Он не содержит учебную метку, название сценария или имя клиента, не подставляет ответы и не выполняет проверку.

## Запуск

Нужен **Node.js 20 или новее**. Сторонних npm-зависимостей нет, `npm install` не требуется.

```sh
git clone https://github.com/KatoWolf/bankguard-demo.git
cd bankguard-demo
npm start
```

Открыть **http://localhost:3000**. Если порт занят: `npm start -- --port 3001`.

[Инструкция для Windows](docs/windows_ru.md). Не открывайте `index.html` двойным щелчком: ES-модулям нужен HTTP-сервер. После скачивания проекта интернет и API-ключи для работы демо не нужны.

```sh
npm test
npm run build
npm run demo:verify
```

Сборка создаёт статические файлы в `dist/`. Последняя команда воспроизводит 9 экспериментов без браузера; для чистого JSON используйте `node scripts/verify-demo.js > demo-report.json`. Это проверка расчётов, не замена интерактивного показа.

**Стек:** HTML, CSS, JavaScript ES modules; Node.js для локального сервера и тестов. Нет ML, backend-хранилища и авторизации. Локальный сервер слушает только `127.0.0.1`, раздаёт явный список ресурсов через GET/HEAD и не предназначен для production. GitHub Pages не развёрнут; CI сайт не публикует.

## Как считается риск

| Признак | Баллы |
|---|---:|
| Сумма ≥ 5 обычных переводов | 25 |
| Новый получатель | 15 |
| Новое устройство | 20 |
| Не менее 5 переводов за час | 20 |
| Сообщение клиента о давлении звонящего | 35 |

Сумма ограничивается 100; при `балл ≥ порог` сценарий направляется на ручную проверку. Версия правил: `rules-1.0`. Веса заданы для демо, не обучены на банковских данных. Давление звонящего не определяется автоматически: это входной флаг.

Учебная метка используется только для оценки ошибок, **не для скоринга**. При пороге 50 на сюжетном наборе: TP=5, FP=1, FN=2, TN=8; precision=5/6, recall=5/7. Решения аналитика не изменяют эти метки и не переобучают правила.

Обзор всех порогов считает все тревоги **до ограничения ёмкости**. Отдельный расчёт с лимитом относится ко всей выборке, без времени поступления и SLA, и предполагает идеальное распознавание fraud среди рассмотренных кейсов. Это не измерение качества работы аналитика и не рекомендация банковского порога.

## Сохранение и безопасное использование

- **Только вымышленные данные.** Приложение не отправляет введённые данные во внешние сервисы; это не разрешение использовать реальные сведения клиентов.
- Состояние живёт в памяти вкладки и теряется при закрытии, перезагрузке или сбросе. Перед выходом сохраняйте демо-сессию; **черновики комментариев не экспортируются**. Предупреждение браузера о закрытии не гарантировано.
- Восстановить можно только файл демо-сессии со встроенным набором: до **2 МБ и 5000 записей**. Баллы пересчитываются. Пакет кейса, журнал и отчёт эксперимента не являются файлами восстановления.
- Сброс и замена предупреждают о решениях/черновиках. Устаревшее чтение файла не должно заменять новую локальную работу. При превышении лимита новое решение не добавляется; история автоматически не удаляется.
- Комментарии и выгрузки редактируемы, не подписаны и **не являются защищённым банковским аудитом**.

**87 автоматических тестов**, сборка и воспроизводимый CLI-отчёт прошли локально. [Последние запуски CI](https://github.com/KatoWolf/bankguard-demo/actions).

Тесты покрывают риск-логику, все 100 порогов на трёх наборах, импорт/экспорт, гонки чтения сессий, границы числового ввода и локальную раздачу файлов. Проверки разметки и обработчика сервера не заменяют браузерный или промышленный аудит.

**Ручная браузерная проверка последней версии не подтверждена.** Прежняя проверка Chrome относится только к v1.1. Последние изменения интерфейса, скачивание/восстановление файлов, мобильный вид и доступность требуют приёмки в разрешённой среде. Нет полного E2E, банковского пилота или production security review.
