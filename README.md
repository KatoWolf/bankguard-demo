# BankGuard

**Объяснимый антифрод-симулятор для банковских переводов.** Hackathon MVP на синтетических данных. Помогает риск-аналитику понять причины тревоги, принять решение и оценить компромисс между пропусками и лишними проверками.

## Запуск за минуту

Нужен Node.js 20+; сторонних зависимостей нет. Установка `npm install` не требуется. Для Windows: [пошаговый запуск](docs/windows_ru.md).

```sh
git clone https://github.com/KatoWolf/bankguard-demo.git
cd bankguard-demo
npm start
# открыть http://localhost:3000
```

```sh
npm test       # 72 теста правил, импорта, экспорта и воспроизводимости
npm run build  # статические файлы в dist/
```

Не открывайте index.html через file://: ES-модулям нужен HTTP-сервер. `dist/` можно разместить на любом статическом хостинге.

## Что работает

- **Мониторинг:** 16 фиксированных сценариев, поиск и фильтрация, карточка с объяснением каждого сигнала, CSV.
- **Симулятор:** сумма, обычная сумма, число переводов за час, новый получатель, новое устройство, давление звонящего.
- **Лаборатория правил:** порог 1–100, confusion matrix, precision/recall, ложные тревоги и пропуски.
- **Ручная проверка:** снять с проверки или эскалировать с обязательным комментарием; JSON-журнал содержит время, порог, правила и балл.
- **Приватность:** нет внешних запросов из приложения, аккаунтов, банковских реквизитов или API-ключей. Вводите только вымышленные данные.

## Как считается балл

| Сигнал | Баллы |
|---|---:|
| Сумма не менее 5 обычных переводов | 25 |
| Новый получатель | 15 |
| Новое устройство | 20 |
| Не менее 5 переводов за час, включая текущий | 20 |
| Клиент сообщил о давлении звонящего | 35 |

Баллы суммируются и ограничиваются 100. `risk >= threshold` направляет сценарий на ручную проверку. Балл **не вероятность** и не доказательство мошенничества. Веса заданы для демо; они не обучены на банковских данных. Признак давления не выводится скрытно: нужен ответ клиента.

При пороге 50: TP=5, FP=1, FN=2, TN=8, precision=5/6, recall=5/7. Это проверка поведения 16 авторских сценариев, **не обещание эффективности в банке**. Метки не используются при расчёте риска.

## Проблема банка

Социальная инженерия может вынудить клиента самостоятельно подтвердить перевод. Банк должен приоритизировать проверку и объяснять действия, не превращая каждую необычную покупку в блокировку. BankGuard демонстрирует прозрачный маршрут «сигналы → объяснение → человек → журнал» и лабораторию настройки порога.

Источники и оговорки: [исследование](docs/research_ru.md). [Текст заявки](docs/application_ru.md). [Сценарий защиты](docs/pitch_script_ru.md).

## Ограничения и следующий этап

Это не промышленная система и не интеграция с BCC/НБК. Не блокирует переводы, не определяет виновность людей, не содержит ML. Результаты и журнал живут только в памяти вкладки и исчезают при перезагрузке или сбросе. Экспорт сохраняется лишь по нажатию пользователя. Журнал не защищён от изменения.

Для пилота нужны: согласованный обезличенный датасет, временная train/test-разбивка, оценка PR-AUC/recall при фиксированной ёмкости команды, cost-sensitive пороги, мониторинг дрейфа, RBAC и серверный аудит, retention-политика, security review и проверка требований регулятора. Решения об ограничениях принимает уполномоченная команда банка, не этот прототип.

## Структура

- `src/engine.js` — чистые функции валидации, scoring, метрик, CSV.

## Улучшения v1.1

- Фильтр **Ожидают решения** отделяет необработанные тревоги от уже снятых и эскалированных. Порядок: риск по убыванию, затем ID. Кнопка **Следующая тревога** открывает приоритетный кейс. Решения не меняют синтетическую разметку.

## Защита локальной работы

Исправлены гонки импорта: медленно прочитанный старый файл не заменит более новый импорт; правка во время чтения, сброс или смена набора отменяют применение старого файла. Отказ от замены и ошибка валидации не изменяют решения.

Сброс/импорт предупреждают также о несохранённых черновиках, даже когда журнал ещё пуст. При закрытии вкладки с решениями или непустыми черновиками приложение запрашивает стандартное предупреждение браузера. Оно не гарантировано (особенно на мобильном устройстве) и не заменяет экспорт JSON; черновики в экспорт не входят. Предупреждение остаётся после скачивания, поскольку приложение не может проверить, что файл действительно сохранён.

PDF фиксирует предыдущий срез: 63 теста, разбор FP/FN, пакет кейса и передача разработчику. В числе регрессий — гонки импорта, большие сессии и исключение учебной метки из пакета.

## Надёжность больших сессий

Экспорт сессии хранит компактный JSON только с исходными полями решений, без дублирования вычисленных баллов и причин. После импорта причины пересчитываются; нормализованный файл тоже проверяется на лимит 2 МБ. Добавление решения заранее проверяет лимиты 5000 записей и 2 МБ: при переполнении решение не добавляется, журнал и черновик остаются нетронутыми. Сохраните сессию, затем явно начните новый журнал. История не удаляется автоматически. Проверка лимита не зависит от временно некорректных полей нагрузки. Всего 72 теста.

## Разбор ошибок и передача разработчику

Лаборатория показывает конкретные ложные тревоги (FP) и пропущенные fraud-сценарии (FN), их баллы и причины. Кейс можно открыть в мониторинге; полный список входит в JSON эксперимента. Это помогает объяснять цену правил на синтетике, не подбирает банковский порог автоматически. При пороге50: FP TX-0013=60; FN TX-0012=35 и TX-0010=15. UI нового раздела ещё не прошёл подтверждённый браузерный smoke test.

[Подробная передача следующему разработчику](docs/developer_handoff_ru.md): архитектура, файлы, контракты JSON, алгоритмы, запуск, тесты, известные ограничения и приоритеты развития.

## Пакет разбора операции

В карточке операции доступен раскрываемый пакет: исходные синтетические поля, сработавшие правила и отдельные вопросы/гипотезы для ручной проверки. JSON `bankguard-case-1` не содержит учебную метку fraud, название сценария, имя клиента или произвольные поля. Ответы не собраны; пакет не подтверждает факты банка, не подписан и не выполняет действий. 5 новых тестов проверяют разделение слоёв и отсутствие метки: текущий итог 72. Браузерный прогон раскрытия/скачивания пока не подтверждён.

## Защита локального сервера

Dev-сервер слушает только `127.0.0.1`, раздаёт явный список ресурсов интерфейса и принимает только GET/HEAD. Произвольные файлы, документация, секреты и ссылки на другой реальный путь не раздаются. Корень определяется по server.js, а не рабочему каталогу. Это локальный инструмент, не production-сервер; не используйте его с реальными банковскими данными. Добавлены 9 socketless-регрессий, всего 72 теста. PDF остаётся датированным срезом на 63 теста.
