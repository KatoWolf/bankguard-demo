# BankGuard: передача следующему разработчику

## 1. Назначение и границы

BankGuard — клиентский антифрод-симулятор для обучения, демонстрации ручного разбора и исследования компромиссов правил. Пользователи: антифрод-аналитик и владелец правил. Проблема: ограниченная ёмкость команды, необходимость объяснять тревоги и понимать ложные проверки/пропуски.

Это **не банковская система**. Нет интеграций, ML, реальных переводов, автоматических блокировок, авторизации, backend-хранилища или подтверждённого эффекта на потери. Только встроенная синтетика. Не импортировать реальные клиентские данные. Журнал и JSON не подписаны.

## 2. Быстрый запуск

Node.js 20+; Git или распакованный ZIP. Сторонних npm-зависимостей нет, `npm install` не нужен.

```sh
npm start
npm test
npm run build
npm run demo:verify
```

Открыть http://localhost:3000. При занятом порте: `npm start -- --port 3001`. В Windows/PowerShell можно использовать `npm.cmd`, не отключая execution policy. См. [windows_ru.md](windows_ru.md). Не открывать index.html через file://.

`npm run build` копирует HTML/CSS и src в dist. Это сборка статических файлов, без bundler/transpilation. Документы и локальный сервер в dist не входят. Сервер слушает 0.0.0.0: не считать его защищённым production-сервером, не выставлять наружу без отдельного проектирования. Развёртывание GitHub Pages не выполнено и не входит в текущий CI.

## 4. Поток данных и состояние

ES-модули исполняются в браузере; приложение не делает внешних запросов за банковскими данными. app.js хранит текущий набор, threshold, selected ID, log, Map resolutions, Map commentDrafts и последнюю симуляцию. Поиск/фильтр хранятся в элементах DOM. Перерисовка идёт через render → detail/lab/audit.

Решение добавляется в начало log; resolutions содержит последнее решение по ID. Повторные решения допустимы, история сохраняется. Количество решений в статистике — записи, не уникальные операции. Черновики сохраняются при переключении кейсов, но не экспортируются. После закрытия/перезагрузки память теряется; сохранение сессии — явное скачивание JSON, не localStorage.

Лабораторные метрики считаются по исходным synthetic labels и текущему порогу, а не по решениям аналитика. Очередь исключает ID с решением, но изменение решения не «исправляет» оценку качества правил.

## 5. Операция и риск-логика

Поля: id/title/client, amount, usualAmount, transfersHour, newRecipient, newDevice, callerPressure, fraud. Последнее поле — авторская метка, только для лаборатории. Клиентские названия вымышлены.

Числа должны быть конечными; суммы >0 и ≤10 млрд; transfersHour целое 0–10000; три флага строго boolean. Суммы в демо обозначены тенге. В симуляторе нулевое количество переводов технически допускается валидатором; для банковской семантики «включая текущий» это потребует уточнения при пилоте.

| Условие | Баллы |
|---|---:|
| amount / usualAmount ≥5 |25|
| Новый получатель |15|
| Новое устройство |20|
| transfersHour ≥5 |20|
| Сообщение о давлении звонящего |35|

Результат = min(100, сумма); причины сохраняют исходные баллы и могут в сумме давать 115. Риск не вероятность. Порог — целое 1–100; review при score ≥ threshold. VERSION=`rules-1.0` — версия правил, не версия приложения. Изменение весов требует версионирования и пересмотра совместимости сессий.

Порядок очереди: риск по убыванию, затем ID через localeCompare. Ёмкость 0–5000 — лимит всей выборки, не модель поступления во времени/SLA. Recall с лимитом предполагает идеальную идентификацию fraud в рассмотренных кейсах. Время проверки >0 и ≤120 минут — допущение, не измерение.

Стресс-наборы в UI: 200/1000, seed 2026. Метка создаётся до скоринга; распределения пересекаются. 16 сюжетных сценариев имеют 7 fraud-меток. При пороге50: TP5/FP1/FN2/TN8. При пороге1: 13 проверок, FP6/FN0. Не переносить эти показатели на банк.

## 6. Разбор ошибок правил

errorCases(rows, threshold) возвращает {synthetic:true,falseAlerts,misses}. Каждый элемент содержит ID, title, risk, threshold, reasons, syntheticLabel, review. Списки сортируются риск↓/ID; UI показывает до 5 каждого типа, отчёт включает все. Клик меняет мониторинг на выбранный ID и открывает карточку. Это анализ после расчёта, метки не передаются в правила.

Эталон при пороге50: FP TX-0013 (60); FN TX-0012 (35), TX-0010 (15). Эти случаи помогают объяснить ограниченность правил, а не автоматически подобрать «лучший» банковский порог.

## 7. Файлы экспорта и импорт

Различать четыре JSON:
- **case**: схема `bankguard-case-1`, synthetic=true, transactionId, facts (source/values), signals (rulesVersion/risk/threshold/reviewSuggested/reasons), questions (question/hypothesis/answer=null), status=not_verified, automaticAction=false, limitations. Это read-only пакет для обсуждения, не выполненный чек-лист, не импортируемая сессия и не решение. Строгий allowlist исключает fraud, title, client и лишние поля; название сценария может раскрывать авторскую метку и намеренно не экспортируется.
- **audit**: журнал с рассчитанными полями, только для просмотра. Не является импортируемой сессией.
- **experiment**: метрики, сравнение baseline50, нагрузка, ёмкость, errorCases, seed, допущения и предупреждение. Не импортируется.
- **session**: единственный поддерживаемый формат восстановления.

Сессия: schema=`bankguard-session-1`, synthetic=true, version=`rules-1.0`, datasetSize ∈ {16,200,1000}, threshold, minutesPerReview, capacity, entries. Запись содержит id, action (`Снято с проверки` или `Эскалировано`), note (непустой, ≤240 JS code units), time (дата, нормализуется в ISO), threshold (обязательный). Экспорт компактный, только эти исходные поля; risk/reasons/version записи пересчитываются при чтении.

Лимиты: 2 000 000 UTF-8 байт и 5000 записей; проверяется также размер нормализованного экспорта. UTF-8 BOM поддерживается, UTF-16 нет. Набор восстанавливается из встроенных данных, произвольные операции не принимаются. Порядок entries — новые решения первыми; при восстановлении Map строится в обратном порядке. Дата не доказывает подлинность/порядок реальных событий.

appendSessionEntry проверяет возможность экспорта **до** мутации log. Для лимита резервируется максимальный разрешённый заголовок параметров, чтобы временно невалидный input нагрузки не мешал решению. При переполнении UI оставляет журнал и черновик, предлагает сохранить и начать новый журнал; автоматического удаления истории нет.

CSV имеет BOM, экранирование кавычек и защиту от формул, включая пробельные префиксы. Не считать это универсальным защитным контуром для произвольных импортов: их здесь нет.

## 8. Асинхронность и защита локальной работы

createImportController использует revision: более новый импорт или invalidate отменяет применение прежнего чтения. Локальные input-события, reset и запись решения инвалидируют чтение. Устаревшие результаты/ошибки не меняют статус новой операции. Ошибка парсинга и отказ confirm не изменяют сессию.

hasLocalWork учитывает записи и непустые черновики. Сброс/смена набора/импорт требуют подтверждения при локальной работе. beforeunload просит стандартное предупреждение браузера, но оно не гарантировано, особенно на мобильных. Экспорт не выключает предупреждение: приложение не знает, сохранён ли скачанный файл.

## 9. Проверки и точные пределы уверенности

72 автоматических теста: правила/границы, матрица, ёмкость, CSV, детерминизм, сессии/большие журналы, гонки импорта, FP/FN и статическая доступная разметка. npm test использует Node --test без shell glob. CI не содержит браузера или deployment.

Ручной браузерный smoke test последней версии **не подтверждён** из-за ограничения рабочей среды. Исторические Chrome-проверки относятся к v1.1, не к новым импортам или разбору ошибок. Нет полного E2E, аудита экранным диктором, production security review или банковского пилота. Статический тест разметки не проверяет фокус/диалоги реального браузера.

Перед защитой выполнить [demo_walkthrough_ru.md](demo_walkthrough_ru.md) и [qa_ru.md](qa_ru.md) на разрешённом компьютере. Для CLI-резерва: `node scripts/verify-demo.js > demo-report.json`; это не замена UI-демонстрации.

## 10. Следующие задачи по приоритету

1. Ручной/E2E браузерный прогон на разрешённой среде: импорт, отмена, два файла подряд, скачивание, клавиатурный фокус, 390/1440 px; не обходить ограничения среды.
2. Отделить DOM и состояние app.js в контроллеры, сохранив текущие регрессии; сейчас часть UI-логики компактна и требует осторожности.
3. Добавить миграции схем и версионирование набора/генератора до изменения встроенных данных: текущий импорт привязан к стабильности этих fixtures.
4. До пилота согласовать источник/законность данных, временную оценку качества, baseline, стоимость ошибок, человеческий процесс и семантику сигналов. Не подбирать production-порог по синтетике.
5. Только при отдельном проектировании: RBAC, серверный аудит, безопасное хранение/retention, threat model, интеграции в shadow mode и нагрузочные проверки.

Не добавлять реальные переводы/автоблокировки или публикацию сервиса как побочный эффект рефакторинга. Репозиторий публичный: секреты и персональные данные не коммитить.

## 11. Пакет разбора: важные инварианты

casePacket(t,threshold) использует engine.decision, но не synthetic label. Возвращает одинаковый результат при инверсии fraud. Каждое правило добавляет вопрос и явно неподтверждённую гипотезу; общий вопрос сохраняется даже при нулевом риске. Код не связывается с клиентом, не запрашивает секреты, не блокирует счёт и не подставляет ответы. UI показывает пакет в details карточки и позволяет скачать JSON; клики/скачивание не проверены реальным браузером. Следующему разработчику нельзя переименовывать `not_verified` в «проверено» без отдельного процесса подтверждения.

## Контракт dev-сервера

`server.js` экспортирует `createHandler(root)` без открытия порта при импорте. Запуск CLI привязан к loopback `127.0.0.1`; поддерживаются GET/HEAD. `PUBLIC_FILES` задаёт точный список клиентских файлов. При добавлении модуля в src обновить этот список; тест сравнивает его с каталогом. Корень не зависит от cwd. Проверка realpath отклоняет как выход наружу, так и перенаправление на приватный файл внутри корня. Проверки handler выполняются без sockets; реальный браузерный прогон не подтверждён. Это не защита от локального злоумышленника с правами записи: гонки изменения файлов и production threat model не покрыты. Для публикации нужен отдельный проверенный static hosting.
