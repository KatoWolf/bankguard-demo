# Проверка v1.2 перед защитой

Текущий итог: 82 теста; CI проверяет тесты и сборку в 6 конфигурациях Windows/Ubuntu × Node.js 20/22/24 ([CI](https://github.com/KatoWolf/bankguard-demo/actions)). Ниже сохранена история этапов; промежуточные количества тестов не являются текущим итогом. Ручная браузерная проверка последней версии не подтверждена.

1. `npm test` (82 теста), `npm run build`, `npm start`.
2. В мониторинге выбрать 1000 стресс-операций и загрузить набор. Убедиться, что счётчик равен 1000.
3. Открыть следующую тревогу. Без комментария решение не сохраняется. Добавить вымышленный комментарий, эскалировать. Очередь уменьшается на один.
4. В лаборатории выставить ёмкость 0: проверят 0, recall с лимитом 0%, все тревоги остаются в очереди. При ёмкости 5000 recall совпадает с recall порога.
5. Скачать отчёт эксперимента. Проверить dataset, comparison, workload, capacity и предупреждение о синтетике.
6. В журнале сохранить демо-сессию. Отменить сброс: решение остаётся. Подтвердить сброс: журнал пуст. Восстановить сохранённый файл: решение и параметры возвращаются.
7. Импортировать некорректный JSON: появляется ошибка, текущие решения остаются. Повторный импорт того же файла должен работать.
8. Проверить ширины 390 и 1440 px, клавиатурную навигацию, поиск без результатов и повторные смены набора.

Это список приёмочных проверок, а не заявление об их выполнении. Unit tests и сборка v1.2 выполнены. Браузерная проверка v1.2 в текущей среде заблокирована ограничением запуска Chromium/недоступностью локального сервера из отдельного браузера.

Не использовать реальные данные. Наборы намеренно содержат ошибки правил. Ёмкость относится ко всей выборке, без моделирования времени поступления или SLA. Решения аналитика не меняют исходные метки. Сохранённый JSON редактируемый и не имеет подписи.

## Аудит v1.2: импорт, экспорт и автоматизация

- На этом этапе: 33/33 unit tests и `npm run build` прошли на Node 24.
- Исправлено: импорт теперь требует явно заданного целочисленного порога и в сессии, и в каждой записи. Отсутствующий порог больше не превращается в некорректное состояние интерфейса.
- CSV нейтрализует формулы с начальными пробелами, табуляцией и переносами строк.
- Сброс демо возвращает длительность проверки и ёмкость аналитиков к 5, очищает ошибку симулятора.
- Добавлены проверки баланса очереди и fraud-меток на 1000 сценариях при разных порогах и ёмкостях, а также порядка повторных решений после импорта.
- GitHub Actions запускает тесты, сборку и сравнение статических модулей на Node 20/22/24 при push и pull request. Workflow не публикует сайт и имеет только `contents: read`.
- Эти автоматические проверки не заменяют браузерный smoke test. Ограничение браузерной проверки v1.2, указанное выше, сохраняется.

## Независимый аудит правил

На этом этапе 38 тестов покрывали все 32 комбинации пяти правил, эталонные баллы каждого из 16 сюжетных сценариев, пустые наборы и граничные параметры. Исправлены обход проверки порога на пустой выборке и несоответствие лимита ёмкости между расчётом и импортом (единый диапазон 0–5000).

Recall с лимитом — верхняя оценка охвата при предположении, что аналитик безошибочно определяет fraud среди выбранных проверок. Это не измеренная эффективность человека. Предположение явно добавлено в интерфейс и JSON-отчёт вместе с областью лимита, порядком очереди и seed. Решения в журнале не меняют лабораторные показатели. Браузерная проверка по-прежнему не подтверждена.

## Актуальность результата симулятора

Изменение любого входного поля немедленно убирает старый результат и просит пересчитать риск. Неуспешный расчёт тоже очищает сохранённые входы; смена порога больше не возвращает старую оценку. `src/simulator.js` отделяет состояние от DOM. Четыре регрессии покрывают сброс, ошибку после успеха, изоляцию копий и восстановление после ошибки. Всего 76 тестов; ручная браузерная проверка этого сценария не подтверждена.
